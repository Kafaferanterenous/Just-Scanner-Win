# Non-destructive session contract v2

Each session is rooted in a user-selected local directory and contains:

```text
session-root/
  session.jscan
  session.jscan.bak
  originals/
  previews/
  derivatives/
  exports/
```

`session.jscan` is a bounded, line-oriented v2 manifest. Fields are tab
separated and text fields use percent encoding. The format starts with
`JSCAN<TAB>2`, contains exactly one `SESSION` record, bounded `PAGE` and
`HISTORY` records, and ends with `END`. Unknown, duplicate, malformed,
oversized, absolute, or parent-traversing values fail closed.

Version 2 adds signed brightness and contrast fields to each page. Both are
bounded to -100 through 100. The loader accepts valid v1 manifests, defaults
both values to zero, and publishes v2 on the next save. Invalid v2 tone values
fail closed; no master bytes are changed during migration.

Page identifiers and original filenames are generated by the core. A current
master is stored under `originals/`; a rescan creates the next revision and
moves the prior relative path into page history. Rotation is restricted to
0/90/180/270 degrees. Crop rectangles must have non-zero size and remain
inside the original dimensions. Reordering must be an exact permutation of all
known page identifiers. Exclusion is reversible and never deletes a master.
Brightness and contrast are reversible derivative settings. Rescan resets
rotation, crop, brightness, and contrast while retaining the prior master in
history.

Saving writes and flushes `session.jscan.tmp` first. Publication retains the
previous manifest as `session.jscan.bak`. Loading ignores any abandoned stage
file. If the current manifest is invalid, the loader may recover only from a
fully valid backup and reports that recovery explicitly.

The format is intentionally small for the mock milestone. Any future schema
replacement must include a versioned migration, preserve all masters, and be
tested against corrupted and interrupted input before adoption.
